# 扫描运行时升级 · 2026-09-24

在已部署第三人称精扫 v5m 的基础上，VisionCortex 增加按实际模型依赖区分的扫描缓存，以及按像素字节预算限制的解码队列。模型权重、采样率、原画尺寸和生产 GPU 配额保持；旧代码及模型可回滚。完整产品目标继续执行。

## 实际改动与对照

旧缓存把其他视角和阶段的模型配置也算入身份，换模会引起无关重算。新版 `visioncortex-device-scan/2` 显式绑定实际选中的角色、阶段、模型及哈希，保留来源、时钟、采样和相关代码校验。旧 v1 缓存保留，首次进入 v2 会冷启动；没有未经验证地把旧结果当成新结果。

检测队列默认按 64 MiB 的 BGR/灰度像素预算限制帧数，1080p 下请求 64 帧收紧为 6 帧。有序预取的全部工作队列共享另一份 64 MiB 预算，同时只允许与解码 worker 数相同的未消费分块；完成但未消费的 future 不再无限堆积。这些限制不覆盖模型、解码器内部及其它缓存，不能当作进程内存上限。

同一真实 16 秒片段、320 帧、20 Hz、同一 v5m TensorRT 引擎：

| 指标 | 旧代码 | 新代码 |
| --- | ---: | ---: |
| 检测 JSONL | 320 帧 | 320 帧，逐字节一致 |
| 观测队列积压峰值 | 19 帧 | 5 帧，有效上限 6 |
| 单次扫描耗时 | 17.89 秒 | 15.27 秒 |
| 进程峰值 RSS | 1,505,288 KiB | 1,531,792 KiB |

短片没有证明总 RSS 下降，也不能从一次运行宣称稳定提速。改动无关第一人称引擎后，新缓存 0.007 秒命中相同账本；改动实际第三人称引擎仍使缓存失效。首次隔离尝试因 CIFS 临时协调数据库锁失败，原始失败保留；后续使用已有 GPU 锁及资源检查完成，生产配置未修改。

181 项相关检查通过。新的预取积压用例在旧源码上失败、修复后通过。修改文件 Ruff 和编译检查通过；上游全仓另有两项既有 `rtp_receiver.py` 风格问题，本轮未修改。

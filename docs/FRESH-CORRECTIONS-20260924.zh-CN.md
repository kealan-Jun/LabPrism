# 新视频纠错与检测训练 · 2026-09-24

本轮完成了新增标注和一次真实 GPU 训练。纠错画面明显改善，但旧验证集回退，候选未替换生产模型。第一人称继续使用已部署的 v8；第三人称粗扫 v2、精扫 v5m 保持。完整产品目标继续执行。

## 标签和训练

AnnotationWorkbench 从上一轮真实新视频抽取 45 秒和 85 秒原幅，保留原视频摘要、原生 PTS、相机身份、视角及来源组。两遍实际查看后，经 Store API 和版本检查保存为 `reviewed_partial / all_visible_outside_ignore`：新增 **2 图、19 个已知检测实例**，密集或不确定区域保持 ignore。这是项目复核，不是独立人工真值。

标签区分棕色瓶身与独立红盖；同一人的两只袖子及衣襟属于一件实验服。三只可见手只确定了 **4 个关节点**，其余 59 点保持未知；本轮没有训练手姿模型，也没有把四个点说成完整骨架标注。

从线上 v8 对应权重初始化，沿用既有部分监督训练器与旧样本回放；冻结 **107 train / 16 val**，验证图、标签和版本保持。实际执行 30 轮、640 输入、RTX 3090 Ti、FP16，batch 16 / 尾批 11；训练及验证共 **64.632 秒**，训练器计时 **63.057 秒**，峰值已分配 **4,784.04 MiB**。新建优化器，非 optimizer resume。

原自动训练质量保持未解除。数据、标签、日志、评估均在工作台 NAS；模型与冻结代码快照本地保存。沿用真实 `development-reuse-v2` 来源图：9 月 23 日已存在单独训练组件，不把该日错误合并为 9 月 15 日，也不声称这些素材独立。

## 同条件结果

以下为置信度 0.25、预测 NMS IoU 0.7、同一批 16 张固定开发验证图，214 个实例。线上实际 TensorRT 引擎与 PyTorch 候选分别标明后端，不把权重文件比较等同于新引擎验收。

| 模型 | 正确检出 TP | 误报 FP | 漏检 FN |
| --- | ---: | ---: | ---: |
| 当前 v8 TensorRT | 176 | 22 | 38 |
| v8 PyTorch 父权重 | 173 | 16 | 41 |
| v10 PyTorch，30 轮 | 170 | 21 | 44 |
| v8/v10 权重混合，候选占 25% | 172 | 19 | 42 |
| v8/v10 权重混合，候选占 50% | 171 | 21 | 43 |

两个混合候选使用评估前声明的比例，是权重派生，不是另外两次训练。历史报告还使用第一人称最终同类去重 IoU 0.55；按该旧比较口径重新计算，v8 为 **175/13/39**、v10 为 **169/12/45**。该口径与目前未配置第一人称最终去重的实际服务分开报告，不能混用数字。

两张新增训练图，在已知实例及已复核区域范围内：v8 **11TP / 3FP / 8FN** → v10 **17TP / 0FP / 2FN**。未知区域按冻结规则排除，不能把这个误报数解释为整幅没有误报。实看对照发现：整瓶误判瓶盖消失、红盖边界恢复，但瓶身仍漏检；称量纸、白盖、台面纸卡以及 85 秒的天平/药匙恢复。旧验证的天平、纸张、试剂瓶、手套、枪头盒、管盖各少检出一个实例，因此拒绝当前候选替换。

训练器端到端分支的 mAP50–95 从 0.69204 到 0.69777，不能覆盖实际部署分支在固定阈值下的回退结论。下一轮应加强旧能力保持约束及回放覆盖，不重复相同少量样本微调。

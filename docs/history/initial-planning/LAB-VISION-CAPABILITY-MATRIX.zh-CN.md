## 2. 候选模型如何选到适合我们的最好结果

每个核心模块至少比较一个可运行基线与一个改进方案，先用预训练推理筛选；把 GPU 训练和精修标注投入有潜力的方案，避免在单卡上同时全量训练所有候选。候选列表随新证据更新，登记选中与淘汰原因。

| 模块 | 第一批候选方向 | 选型重点 |
| --- | --- | --- |
| 检测 / 实例与视频分割 | 现用检测基线；SAM 3.1、Grounding DINO + SAM 2.1 辅助标注；YOLO26-seg 与可转换的小型分割模型 | 本地玻璃/密集器材表现、每视角漏检、可修正成本、推理资源；沿用主计划来源记录 |
| 语义分割 | SegFormer 等专用语义模型，与低延迟 CNN 语义方案比较 | 明确场景语义类与 ignore；按 mIoU 和边界质量选型，单独验证 NPU 算子；选定代码/权重许可后才使用 |
| 手部姿态 | MediaPipe Hand Landmarker 作为 21 点与流式基线；可训练的专用手部关键点方案作为改进候选；需要 3D 时增加 HaMeR 系列研究对照 | 戴手套/双手交叉/小手/高速运动/握持工具测试；检测失败计入，不只统计检测成功的漂亮骨架；重建所需 MANO 权限单独核验 |
| 跟踪 | ByteTrack 类轻量关联与分割感知时序关联 | 真实遮挡下的身份连续性；外观特征不能把同型号烧杯混为同一实物；平滑不能以明显延迟换取漂亮曲线 |
| 动作与步骤 | 明确关系/时序特征基线，比较 InternVideo 系列视频表征 + 时序定位/分段头；ActionFormer 可作定位基线 | 域内动作混淆、长视频分段、数据量与单卡负担；大模型生成的字幕仍需事件证据，不能代替真值 |
| 深度 / 3D | 有标定条件的几何基线与 VGGT 等视觉几何模型对照 | 透明玻璃失效、动态手/器材与静态背景分离、尺度、同步；先验证，不能直接输出可信毫米距离 |

来源：[SegFormer 官方实现](https://github.com/NVlabs/SegFormer)、[MediaPipe 手部关键点说明](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker)、[HaMeR 官方实现](https://github.com/geopavlakos/hamer)、[InternVideo](https://github.com/OpenGVLab/InternVideo)、[ActionFormer](https://github.com/happyharrycn/actionformer_release)、[VGGT](https://github.com/facebookresearch/vggt)。它们是已核验任务方向的候选，不是已经在本项目跑通、已确认产品许可或已确定的最终模型。

手部输出的左右手身份与相机镜像/旋转约定要统一。模型输出的局部 3D 手坐标不能直接当作相机标定后的全局坐标。手部/语义模型的正式数值门槛在 W1–W2 数据与基线具备后、接触封存测试前冻结，不伪造当前分数或临时改用有利指标。

## 3. 系统质量优先的统一选择规则

先保证每个模块的质量底线，再在满足质量的方案中比较泛化、延迟、显存/内存、量化损失及维护成本。保留“离线效果较好”和“在线/边缘运行较好”的不同配置，而不是把一个大模型强行用于所有任务。每个配置有确切用途、适用场景和证据。

模块都在同一套来源分组规则下评测，避免检测和手部模块分别好看、串起来因时间戳或裁剪坐标不一致而失效。除单模块指标外，必须评估完整事件链：器材找对、mask 对齐、手识别正确、关系关联正确、动作时间准确、OCR 对应正确设备。下游测试既测理想输入，也测真实上游预测输入，显式量化错误累积。

数据集按任务保存 `bbox / instance_mask / semantic_mask / keypoints / tracks / relations / events / text / calibration` 的版本与复核状态。某图完成框标注，不代表它同时完成 mask、手关键点或动作标注。视频级来源分组贯穿全部任务，禁止一个模块训练用过的片段再冒充另一个共享组件的未见测试。

所有推理输出必须携带模块模型版本、源帧与时间、坐标系及可用性。实时模式里尚未产生的动作不可借用未来帧；离线双向分析必须标明，分别统计在线延迟与离线耗时。

## 4. 时间与完成口径

8 周计划继续推进完整系统试用版，同时开展所有相关能力的基线、数据与接口工作。W4 主链路包括检测、实例/语义分割、跟踪和手部骨架初版，W5 接入动作、OCR 与时间线，W8 按模块验收。

用户新增的“所有能力做到最好”提高了目标范围，不能把原有单卡/数据条件下的日期等同于每个模块都必然达到最优。高精度 3D、全新器材族、复杂长步骤和实板 NPU 的质量取决于对应真值与硬件。缺条件时仍交付可复现基线、失败样例和具体缺口，保留未完成项继续推进；不能为了宣布完成删除模块或降低质量要求。若需要延长某项工期或增加资源，在第一周实测后给出具体依据。

复现清单中每项对应本矩阵模块，状态与测试证据写入 `capability-scorecard.json`；数字未知写 null，未跑的模型不写成已验证。对方未提供同条件模型输出/指标时，性能比较记为不可比较，持续展示我们自己的可复现改进。

# 官网演示复现与提升：产品验收清单

版本：2026-09-18 / v1.2。关联计划：实验室视觉泛化 8 周项目。

用户补充目标：复现 Transfyr 官网视频中的视觉能力与展示体验，并在实际使用中做得更好。此要求覆盖完整官网、运行模型、视频产品与部署交付，纳入同一条工程主线。以下为完整验收要求。当前 REF-01/03/04/06 的部分短片功能已真实运行，其余能力及独立质量仍待验证；三段 8 秒诊断片段不满足 W4 三个不同实验完整视频要求。

## 1. 复现的具体范围

参考为用户截图及已查看的 [Transfyr 技术页演示](https://www.transfyr.ai/technology)。我们独立实现对应功能，使用自有实验素材展示。

| ID | 能力与展示 | 我们的验收要求 | 首次交付 |
| --- | --- | --- | --- |
| REF-01 | 器材逐件检测与彩色实例轮廓 | 每个可识别器材有类别、框和实例 mask；同类多个物体分别显示，mask 与原帧准确对齐；透明玻璃和密集器材纳入测试 | W4 |
| REF-02 | 视频中连续的目标呈现 | 单相机 track ID、颜色与类别保持关联；记录遮挡后的身份切换；跟踪失败可见，不悄悄用新 ID 冒充持续跟踪 | W4 |
| REF-03 | 器材名称及可读标签 | 中文名称、必要时英文名称；真实有依据的规格/设备绑定；密集场景标签避让、按类别筛选、选择单件查看详情 | W4 基础 / W5 属性 |
| REF-04 | 手部骨架与器材交互 | 裸手/戴手套分别测试关键点；展示交互对象及其证据；不确定结果可返回未知，不用重叠关系编造动作 | W5 |
| REF-05 | 操作字幕与时间段 | 结构化事件驱动的字幕/时间线，标明起止时间、动作和器材；点击事件跳转原视频，能检查发生依据 | W5 |
| REF-06 | 完整实验过程展示 | 连续播放、暂停逐帧、原画/识别结果对照、叠加层开关、目标详情；明确实时输入或离线分析模式，显示模型版本和处理延迟 | W4 主视图 / W5 完整时间线 |
| REF-07 | 语义分割 | 对明确的场景区域/可见材料类别输出像素标签；建立独立语义标签、ignore 和 mIoU 评测，不能把实例彩色叠加直接称为语义分割验收完成 | W4 基线 / W8 验收 |
| REF-08 | 动作与实验步骤理解 | 在连续视频中区分动作、动作起止与步骤归属；同一步骤中的不同操作方式分别记录，提供时间区间和证据 | W5 基线 / W8 验收 |

W4 交付至少 3 段来自不同实验的完整、未剪辑视频，包含密集目标和失败场景。演示里的框、mask、轨迹、OCR 和字幕均来自真实推理结果；动画或人工预置的示例不得作为推理验收。保留原视频、输出记录、参数与模型哈希，使视频能重新生成。

## 2. 在实际使用中做得更好的方向

| ID | 提升目标 | 需要提供的证据 | 关联工作 |
| --- | --- | --- | --- |
| BETTER-01 | 换背景、实物、相机仍识别同类器材 | 封存的新烧杯和新环境测试；第一/第三人称分别报告 Precision、Recall、mask AP 与实验组置信区间 | W1 基准、W3 数据训练、W8 验收 |
| BETTER-02 | 长视频里稳定、可解释 | 类别跳变、身份切换、遮挡恢复统计；点击实例或事件可查看原帧、置信度与轨迹；展示难例 | W4 跟踪、W5 交互、W7 连续运行 |
| BETTER-03 | 仪器读数与操作过程结合 | 面板—文字行—数字/单位—视频时间点的对应关系；小数、负号、设备变化的独立评测 | W5 OCR 与时间线 |
| BETTER-04 | 能长期变好，错误可控制 | 每批数据筛选理由、标注身份、模型父版本和回归结果；候选质量下降时实际保留旧模型，并验证回滚 | W6 模型对照与回滚 |
| BETTER-05 | 能运行和交付到实际硬件 | GPU 完整流程延迟与吞吐；板卡确定后提供 NPU 精度、量化损失、FPS、温升与运行包 | W1 转换探路、W6–W7 部署 |
| BETTER-06 | 第一/第三人称统一使用体验 | 分视角模型与指标；共用视频结果接口及查看入口。有同步时钟证据的多机位可联动回放，否则保留各自时间轴 | W4 接口、W7 系统验收 |

这些是我们的产品改进目标，不据此断言对方产品没有相同能力。拟定数值门槛沿用 8 周计划；达到自己的门槛与超过对方是不同的结论。

## 3. “复现”和“超越”的判定

- **展示能力复现：** REF-01 至 REF-08 的实现逐项通过，并提供真实视频和可运行版本。REF-07/08 同时落实用户补充的完整算法能力要求；不从官网截图推断对方具体语义分割架构。手部/事件模块晚于 W4 主链路，W5 补齐，W8 统一验收；未达到的项不能由其他项平均抵消。
- **相对现有系统改进：** 在同一冻结数据、阈值协议与硬件条件下，报告新旧系统差异；数据规模、模型指标、界面体验和实际延迟分别比较。
- **相对 Transfyr 的性能优势：** 只有取得可比较的系统输出或可信公开成绩，且任务、输入数据、标注、计算口径及硬件条件可对齐，才能报告对应优势。否则标记为“未取得同条件比较证据”，仍完整交付我们的实测结果。

交付对照表中每一项记录 `planned / implemented / verified / not_met / not_comparable`、证据路径、测试条件和剩余问题。状态仅由证据更新，不能根据模型名称、演示观感或排期日期判断已超越。

## 4. 对现有排期的修改

总体仍为 8 周，使用现有 GPU 与 NAS；W4 的交付现在明确包含可操作的视频产品界面、真实分割叠加与跟踪，而不只是模型文件和推理脚本。W5 接入骨架、器材交互、OCR 与可回放时间线。W8 将本清单与模型泛化指标同时验收。

下一步继续执行 W1 来源分组、代表性数据与教师/转换小试；不为增加演示效果跳过数据质量门槛。界面初版可先接固定真实推理结果以验证交互，必须明确离线结果身份，最终由实时/离线运行接口接通。

完整模块、候选模型、数据与指标见 [完整视觉能力矩阵](CAPABILITIES.zh-CN.md)。3D、几何及多模态记录同样登记，不会从产品范围里遗漏；其中实尺度精度和传感器记录需要对应采集条件，不能从单目视频猜出。

## 官网和项目归属

用户已确认完整官网也要做。首页、技术页、演示空间及后续完整站点属于 LabPrism，并按 ROADMAP 与真实模型集成验收。数据集、标注、训练留在 AnnotationWorkbench，经正式交付对接。

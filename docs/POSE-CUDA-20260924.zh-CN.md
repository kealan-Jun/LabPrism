# CUDA 手姿重算 · 2026-09-24

已把接收的 RTMPose 手姿权重接入实际 CUDA 重算入口，并完成固定标签和两段完整视频的 CPU/CUDA 对照。新环境复用已有 PyTorch CUDA 12.4、rtmlib 和 PyAV，原推理环境及生产环境未修改。生产检测继续使用已经部署的第一人称 v8、第三人称 v2。本轮没有新增训练，也没有把手姿诊断权重升级为生产模型。

## 实际修复

原 LabPrism ONNX Runtime 1.30.0 只有 CPU；另一项目已有的 GPU 1.29.0 在真实加载时缺少 `libcublasLt.so.13`，不能仅凭 provider 列表认定可用。独立 CUDA 12 兼容环境采用 ONNX Runtime GPU 1.26.0，通过显式 `.pth` 只读复用原推理依赖，不重复安装整套 Torch/CUDA。下载包的 SHA256 已与官方 PyPI 元数据核对。兼容关系见 [ONNX Runtime 官方 CUDA 说明](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html)。

`load_color_aligned_pose` 现在接受显式运行设备，复用 rtmlib 的 RGB 边界、仿射变换及 SimCC 解码。CUDA 会话禁止 CPU 节点分配和运行期回退，关闭 TF32，ORT arena 上限 1024 MiB；这个上限不包含所有 CUDA context/库内存。GPU 缺失、依赖失败、异常 provider 或无效配置均报错。CPU 历史请求仍可复现。

实际 ONNX profiling 记录 **178 个 CUDA 执行节点、0 个 CPU 执行节点**。输入 `[1,3,256,256]`，输出两组 `[1,21,512]`。CPU provider 仍被 ORT 自动注册，但没有执行本图的计算节点。当前模型是固定 batch 1，未冒称批量 GPU 推理。
